# Casos de uso UML de Lucas · Plan de ejecución

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar `docs/casos-uso.md` con el diagrama UML (`.puml` + `.svg`), 12 fichas Cockburn y la matriz HU → CU → CP-SIS sin huecos.

**Architecture:** Un solo documento Markdown. El diagrama vive en `docs/diagramas/`, con la fuente en PlantUML y el SVG exportado offline con `plantuml.jar` (Java 17, layout `smetana`). La «prueba» es un chequeo de trazabilidad con grep que compara las historias y el documento.

**Tech Stack:** Markdown, PlantUML 1.2024.7 (jar temporal), Java 17, Git Bash.

**Spec:** [docs/superpowers/specs/2026-11-14-casos-uso-design.md](../specs/2026-11-14-casos-uso-design.md)

## Global Constraints

- Fuente de verdad: [historias.md](../../../.claude/planes/historias.md). Si un caso y una historia chocan, manda la historia.
- Español, sin AI-slop ([calidad-codigo.md](../../../.claude/reglas/calidad-codigo.md)): nada de «robusto», «integral», «potenciar» ni párrafos de relleno.
- Identificadores siempre completos: `HU-02`, nunca «HU-01, 02»; `CP-SIS-34`, nunca «34». El chequeo depende de esto.
- Rutas solo de [ARCHITECTURE.md](../../../ARCHITECTURE.md): `POST /sesion`, `GET /yo/estado`, `POST /yo/simular`, `POST /yo/movimientos`, `POST /yo/chat`. Las demás se escriben «por definir».
- Sin marca ni colores de BBVA en el diagrama. Usar el tema por defecto de PlantUML.
- Nunca una cifra que no esté en la historia; los umbrales se citan como «umbral de `config/supuestos.yaml`».
- Commits en español, `docs(arq): ...`, sin coautor ni atribución a IA. Sin push.

## Review Focus

1. **Criterio perdido al agrupar**: un «Dado/entonces» de una historia sin paso, alterno, excepción ni regla en su CU. Se revisa leyendo cada historia contra su ficha (Task 4, paso 3).
2. **CP-SIS mal asignado**: un caso de prueba citado en una ficha que no corresponde a sus historias. Lo cubre el chequeo de la Task 4.
3. **SVG ilegible en A4 o que no carga en GitHub**: más de unos 20 óvalos sin paquetes o textos cortados. Se abre el SVG en el navegador (Task 1, paso 4).
4. **Numeración de alternos incoherente**: «4a» que apunta a un paso 4 que no existe. Se revisa en la Task 4, paso 3.
5. **Excepciones de seguridad repartidas mal**: HU-11 y la excepción de HU-12 en el chat tienen que estar en CU-07, no solo en CU-12. El chequeo de la Task 4 busca «C0002» y «transfiere» en la sección de CU-07.

- [ ] **Step 1: Descargar el jar a la carpeta temporal (scratchpad)**


- [ ] **Step 2: Escribir `casos-uso.puml`**

Contenido que fija el spec:
- Primera línea de comentario: el comando para regenerar (`java -jar plantuml.jar -tsvg docs/diagramas/casos-uso.puml`).
- `!pragma layout smetana` y `left to right direction`.
- Actores: `Cliente` (abstracto), con `Independiente`, `Formal` y `Comisionista o mixto` heredando (`<|--`); `Persona sin historial`; `Banco que integra a Lucas`; secundarios a la derecha: `Motor LLM` y `BCRP`.
- `rectangle "Lucas"` con CU-01 a CU-12.
- `CU-01..CU-09 ..> CU-12 : <<include>>`; `CU-07 ..> CU-05 : <<include>>`.
- Extensiones `<<debería>>`: «Ver resumen de quincena» (HU-22) y «Separar negocio y casa» (HU-25), con `..> CU-01 : <<extend>>`.
- Asociaciones: Cliente con CU-01 a CU-09; Persona sin historial con CU-10; Banco con CU-11; CU-07 con Motor LLM; CU-03 con BCRP.

- [ ] **Step 3: Exportar y verificar que no hay errores**

```bash
java -jar "$SCRATCH/plantuml.jar" -tsvg -failfast2 docs/diagramas/casos-uso.puml && grep -c "CU-" docs/diagramas/casos-uso.svg
```
Expected: sale con código 0 y el conteo es ≥ 12.

- [ ] **Step 4: Revisar legibilidad**

Abrir `docs/diagramas/casos-uso.svg` en el navegador. Expected: ningún texto cortado, sin líneas que crucen óvalos de forma confusa y legible al ancho de A4. Si no, agrupar en paquetes (`package "Ola 2"`) o reordenar.

- [ ] **Step 5: Commit**

